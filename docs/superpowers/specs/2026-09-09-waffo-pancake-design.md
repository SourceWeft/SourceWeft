# Waffo Pancake payment integration

The commercial billing package adds Waffo Pancake alongside Creem. The existing BACKEND_BILLING_PROVIDER selector chooses the active checkout provider. Waffo requires only WAFFO_MERCHANT_ID and WAFFO_PRIVATE_KEY as new credentials. Its environment defaults to test; optional WAFFO_ENVIRONMENT selects prod explicitly for a later production deployment. API keys are bound to their environment in Waffo Dashboard. Credentials never activate a provider.

Store and product IDs are persisted in a provider-settings table, keyed by merchant and environment. A setup command uses the official SDK: zero stores creates one, one store is selected automatically, multiple stores require an explicit CLI selection. SDK calls use its own signing and deterministic idempotency. Setup does not publish products into production.

Pricing and top-up orders use the existing billing_orders and entitlement ledger. Server-calculated cents are converted to USD display strings for SDK checkout; incoming amounts are parsed without floating-point rounding. The resulting product, store, environment and checkout identifiers are bound to the local order. Switching providers does not migrate existing subscriptions or reuse the other provider's checkout.

The public Waffo webhook endpoint reads raw text and verifies the SDK's test/prod key and timestamp checks. It validates the mode and configured store, durably saves the signed event, then returns 200. A PostgreSQL advisory lock serializes processing per provider order; scheduler retries survive API restarts. Fulfillment validates local order/provider/store/currency/amount associations and uses the existing row-locked idempotent ledger. Subscription domain events carry period state; charge-only events do not invent subscription periods. Older subscription state is ignored.

The UI keeps Creem behavior and offers Waffo checkout in a new tab after a user click, preserving merchant page state without relying on automatic popups. Waffo's official consumer portal supports subscription management. Unsupported seat changes fail explicitly instead of calling Creem or pretending to update a Waffo subscription.

Validation includes SDK-backed tests with signed fixtures, invalid signatures and wrong environments, amount/order/store mismatches, duplicate and out-of-order events, database durability, provider switching and Creem regressions. A separate local test deployment uses ngrok, a Dashboard-created TEST key, the requested test card 4576750000000110 and a genuine order.completed callback. Real checkout verification remains blocked while the user's Mac/Dashboard is unavailable; fixture tests are not represented as real payments.

Official references are downloaded from https://docs.waffo.ai/llms-full.txt and https://docs.waffo.ai/integrate/skill. The loaded skill is cached at output/references/waffo/SKILL.md. SDK 0.20.0 types and shipped guides resolve older examples in the skill: checkout no longer takes productType, prices use display strings, and webhook replay tolerance covers delivery retries.
