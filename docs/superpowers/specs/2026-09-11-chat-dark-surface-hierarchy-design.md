# Chat 暗色表面层级设计

## 背景

当前 dashboard chat 的暗色模式中，聊天主内容区和右侧 Hub 都过于接近纯黑，导致工作区域缺少 ChatGPT 风格的柔和深灰画布，也让 Hub 与主区的边界显得生硬。用户希望参考 ChatGPT 的暗色界面，重点改善中间主区的背景色。

## 目标

- 让中间聊天主区使用稳定、可读的深灰背景，接近 ChatGPT 的暗色画布体验。
- 让右侧 Hub 从纯黑提升为略亮的深灰，并保留清晰但克制的分隔关系。
- 保留左侧导航更深的层级，避免三列区域混成一个平面。
- 不改变聊天布局、交互行为、响应式断点或浅色主题。

## 设计方案

沿用现有的语义化主题 token，不在聊天组件内散落新的硬编码颜色：

| 区域 | 目标层级 | 处理方式 |
| --- | --- | --- |
| 左侧导航 | 最深 | 继续使用 sidebar 语义 token，保持导航与会话列表稳定 |
| 中间主区 | ChatGPT 风格深灰画布 | 调整 dark 模式的 `background`，使 `bg-background` 呈现明显但柔和的深灰 |
| 右侧 Hub | 略亮于主区 | 调整 Hub 的 panel 背景使用，使其与主区形成一层可见但不突兀的对比 |
| 输入框、卡片、选中态 | 再高一层 | 继续使用 `muted`、`card`、`accent` 和现有边框 token，避免破坏已有交互层级 |

实现优先修改 `apps/web/app/globals.css` 的 dark 主题基础 token；只有在 Hub 的 `bg-background` 无法独立表达其面板层级时，才在 `SourcesHub` 的 panel variant 增加最小范围的语义化类名调整。主区和加载骨架需保持同一套 token，避免首次加载与实际页面出现闪变。

## 验证

- 运行 web 包已有的 lint/typecheck 或相关测试命令。
- 在暗色模式下确认聊天主区不再接近纯黑，右侧 Hub 比当前更柔和且仍可区分。
- 确认浅色模式未变化。
- 确认响应式 drawer/window 变体仍沿用同样的层级语义。
- 检查 git diff，确保只包含本次暗色层级调整和本设计说明，不覆盖用户已有的未提交改动。

## 非目标

- 不重做侧边栏布局、Hub 的宽度、间距或交互。
- 不引入新的颜色系统、第三方组件或动画。
- 不调整文字、图标、字体或业务逻辑。
