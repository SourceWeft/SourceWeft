# Stripe integration verification — 2026-09-09

## Scope

Stripe is an additional commercial billing adapter alongside Creem and Waffo. Select it with BACKEND_BILLING_PROVIDER=stripe and the existing SaaS/Web checkout flags. STRIPE_SECRET_KEY and STRIPE_WEBHOOK_SECRET are required; STRIPE_TEST_MODE defaults to true and must match the server-side secret key. Credentials alone do not activate payment processing.

The implementation uses stripe 22.6.1 and its 2026-08-26.dahlia API version. Hosted Checkout uses server-calculated USD minor units and inline price data, with metadata linking the checkout, subscription and local order. No publishable key or Price ID environment variables are needed. Adaptive currency conversion, automatic tax and promotion codes are explicitly disabled for this catalog.

The adapter provides subscription/top-up checkout, a bound-customer Billing Portal session, and payment-confirmed team seat updates. Seat increases use immediate invoicing and error_if_incomplete; unconfirmed payment or mismatched seat prices do not change local quota. Existing subscriptions are not moved between providers or Stripe accounts.

The Stripe webhook endpoint verifies raw bytes with the official SDK before writing a durable receipt. It rejects mode mismatches and Connect events, handles completed/delayed/failed/expired Checkout, paid/failed invoices and subscription lifecycle events, and retrieves current Stripe resources before applying state. Invoice-first delivery, stale subscription events and old expired checkout notifications are covered. Failed renewal changes status without replenishing credits or advancing the last paid period. Database locks and the existing order ledger prevent duplicate grants.
