# macOS 0.2.0-rc.1 候选包准备

这是本地验证包准备记录，不是公开发布声明。当前 Release 自动流程只发布 Web/Docker，不会自动上传此处的桌面安装包。

## 版本和构建

- 桌面 package.json、Tauri 配置、Cargo.toml 和 Cargo.lock 的应用版本统一为 `0.2.0-rc.1`。
- 当前本机目标为 Apple Silicon / arm64；Intel 和 universal 包尚未验证。
- 本地验证命令：

```sh
pnpm --filter @sourceweft/desktop exec tauri build --ci --no-sign --bundles app,dmg -- --locked
cargo test --locked --manifest-path apps/desktop/src-tauri/Cargo.toml --bin sourceweft-desktop
```

`--no-sign` 明确用于本地验证。本机目前仅检测到 Apple Development 身份，没有 Developer ID Application 分发身份；不能把这次产物标为已完成 Developer ID 签名或公证。

## 当前验证结果

- Release ARM64 可执行文件与 `SourceWeft.app` 已构建成功；App 的 CFBundleShortVersionString 和 CFBundleVersion 均为 `0.2.0-rc.1`。
- 桌面 Rust 二进制目标的 19 项测试全部通过。
- 应用 ZIP 已保存为 `output/release/v0.2.0-rc.1/macos/SourceWeft_0.2.0-rc.1_aarch64.app.zip`，ZIP 完整性、标识与版本一致性检查通过，同目录提供 SHA256SUMS。
- DMG 未完成：Mac 锁屏时，Tauri 的 `bundle_dmg.sh` 在 Finder/AppleScript 布局步骤等待，最终打包命令失败。需要解锁后重跑同一条打包命令，不能将应用 ZIP 当作 DMG 验收通过。
- 尚未对本候选包执行启动、登录和安装升级 UI 实测，也未上传任何产物。
- 构建日志：`/private/tmp/sourceweft-macos-020rc1-build.log`；测试日志：`/private/tmp/sourceweft-macos-020rc1-tests.log`。

## 服务连接

- Release App 默认打开 `https://sourceweft.com`，原生主机注册默认连接 `https://api.sourceweft.com`。
- 测试其他服务时，分别使用现有的 `NEXT_PUBLIC_WEB_BASE_URL` 与 `SOURCEWEFT_API_BASE_URL` 运行时配置；release 模式要求 HTTPS。
- App 是原生桌面外壳及本地能力实现，不内置整套 Web/API 服务。Docker 验收通过不能证明当前线上 Web 已兼容这个候选包。

## 对外分发前仍需完成

1. 提交桌面版本准备后，运行 `.github/workflows/desktop-build.yml` 验证打包；工作流在 GitHub macOS runner 上制作并校验 DMG，不依赖本机锁屏状态。Windows 结果不替代 macOS 结果。验证包使用 `--no-sign`，只保存在 Actions artifacts，不创建 Release。
2. 以准备分发的最终安装包验证 Developer ID 签名、公证和 Gatekeeper 行为。
3. 在干净安装环境验证启动、登录/深链回调、本地设备注册、目录授权、文件操作、升级和卸载。
4. 验证候选包连接的 Web/API 服务与当前原生协议兼容。
5. 明确授权发布后，再决定把通过验证的 macOS 包接入 Release 附件；当前尚未接入或上传。
